## v2.0.3 —— GitHub 同步独立成窗口；右侧栏不再滚动

### 1. GitHub 同步从右侧栏搬出来，独立成窗口

原来它挤在右侧栏最下面，得往下滚才能看到。现在：

- **顶栏多了一个按钮**（在「N 个时段 · 共 N 小时」右边）：
  - 未登录 → 蓝色的 **「GitHub 同步」**
  - 已登录 → 绿色的 **「GitHub 你的用户名」**
- 点它打开**独立的「GitHub 同步」窗口**，里面是完整功能：
  立即同步 / 检查更新 / 退出登录，并且把操作结果（成功、失败原因）用文字写在窗口里，
  不再靠弹一堆对话框

### 2. 右侧栏改成自适应，不再滚动

右侧原来各卡片的高度是写死的（日历 300、统计和工具各自算），加起来超出可视高度就出滚动条。

现在改成：**先量出统计卡和工具卡的实际高度，剩下的全给日历**，并把日历高度夹在
250–340 之间。右侧内容于是永远正好等于可视高度，**不会再出现滚动条**。

### 3. 顺手修掉两个 bug

**（a）「检查更新」永远说没有新版**

`JavaScriptSerializer` 把嵌套数组反序列化成 **`ArrayList`**，而代码里判断的是 `is object[]`，
结果资产列表一个都解析不到，下载地址始终为空。改成按 `IEnumerable` 处理，两种类型都能吃。

> 这个 bug 一直没暴露，是因为只有真的登录之后才会走到「检查更新」。

**（b）登录后用户名是空的**

登录流程里先调 `CurrentUser()` 再 `SaveToken()` —— 而 `CurrentUser()` 用的是**已保存的**
令牌，那一刻还是空的，自然拿不到用户名。

- 新增 `CurrentUser(token)` 重载，登录时直接用刚拿到的令牌查询
- 另外加了自愈：程序启动时若发现「已登录但用户名为空」，后台补拉一次

## v2.0.2 —— 修复登录报「未能创建 SSL/TLS 安全通道」

点「登录 GitHub」立刻报 `网络错误：请求被中止: 未能创建 SSL/TLS 安全通道`。

### 根因（两层，第二层很隐蔽）

**第一层：TLS 版本。** 用 `csc.exe` 编译出来的程序，运行时被当成旧版 .NET 应用，
`ServicePointManager.SecurityProtocol` 默认只有 `Ssl3, Tls`（**TLS 1.0**），
而 GitHub 只接受 TLS 1.2+，握手直接被拒。

**第二层：静态构造函数压根没执行。** 改成 `SecurityProtocol |= Tls12` 后依然失败 ——
因为 `ClientId` / `VersionTag` 是 **`const`**，编译器把取值**内联**到调用处，
访问 const 成员**不会触发静态构造函数**，那段修复代码从来没跑过。

### 怎么修的

- 静态构造函数改成**赋值** `SecurityProtocol = Tls12`（原来用 `|=` 会把 Ssl3/TLS1.0 留在协商列表里）
- 新增 `GitHub.Init()`，在 `Program.Main` **最开头**显式调用
- Android 端也加了显式 TLS 1.2（防老机型/定制 ROM 关掉）

### 新增 `tools/GhTest.cs`

命令行自检，**直接复用产品代码**，不再靠猜：

```
TLS 协议 = Tls12
[1] HTTPS 连通性 / TLS 握手        [OK]   HTTP 200
[2] 设备码请求（点「登录」走的路）  [OK]   拿到 user_code
[3] 私有仓库读（已登录时）          [OK]   Release / 资产 url / 同步文件
=== 全部通过 ===
```

## v2.0 —— 内置 GitHub 登录：同步打卡记录 + 自动更新

### 1. GitHub 登录（设备码流程）

仓库改成私有之后，程序要访问它就得先登录。用的是 GitHub 官方的 **Device Flow**，和 `gh` 命令行工具同一套机制：

> 点「登录 GitHub」→ 弹窗显示一个 8 位代码（自动复制到剪贴板）→ 浏览器打开授权页 → 粘贴 → 点 Authorize → 完成

- **不需要 client_secret**，所以 Client ID 直接写在客户端里是安全的
- 令牌用 **DPAPI 加密**后存在 `data/github.dat`，只有当前 Windows 用户能解密
- 未登录时会显示「还没有填入 OAuth App 的 Client ID」并提示去哪里配

> 配置步骤（注册 OAuth App、填 Client ID）见仓库根目录的 **`GITHUB_SETUP.md`**。

### 2. 打卡记录同步

「设置与工具」下面多了一张 **GitHub 同步** 卡片：

- **立即同步** —— 与私有仓库的 `sync/progress.txt` 交换打卡记录
- 合并策略是**并集**：手机和电脑各自标的完成都会保留，**只增不减，不会互相覆盖**
- 只有内容真的变了才提交，避免无意义的 commit
- 两端记录的键格式完全一致（`yyyy-MM-dd|HH:mm-HH:mm`），所以能直接互通

### 3. 自动更新

- **检查更新** —— 读取私有仓库的最新 Release，和内置的 `VersionTag` 比较
- 发现新版会显示版本号、体积和更新说明，确认后**下载并自动替换自身**
- 正在运行的 exe 无法自我覆盖，所以会写一个临时批处理：等本进程退出 → 覆盖 → 自动重启

### 4. 顺带的工程改动

- 新增 `src/GitHub.cs`（设备码登录 + REST API + 同步 + 下载）
- `Store.cs` 新增 `DoneKeys()` / `MergeKeys()`
- 编译需要多引用 `System.Web.Extensions.dll`（解析 JSON）与 `System.Security.dll`（DPAPI 加密）
- 右侧多了一张卡片，右栏本来就可滚动，不影响原有布局

## v1.7 —— 修复「点 X 后任务栏图标消失、窗口却还留在屏幕上」

### 原因

关闭逻辑写在 `FormClosing` 里，而且顺序是 `Hide()` → `ShowInTaskbar = false`。这里有两个坑：

1. **在 `FormClosing` 里直接 `Hide()` 不可靠。**
   设了 `e.Cancel = true` 之后，关闭流程**还会继续走完**，它会按自己的逻辑重新应用窗口状态，把刚隐藏的窗口又显示出来。
   正确做法是用 `BeginInvoke` 把隐藏动作**推迟到关闭流程结束之后**再执行。

2. **`ShowInTaskbar` 的赋值会销毁并重建窗口句柄。**
   在已经 `Hide()` 之后改它，重建出来的新窗口可能带上可见状态。
   所以必须**先设 `ShowInTaskbar`、后 `Hide()`**。

这两件事合起来正好就是看到的现象：任务栏图标没了（`ShowInTaskbar = false` 生效了），窗口却还在屏幕上。

### 改法

- 关闭动作改成 `e.Cancel = true` + `BeginInvoke(HideToTray)`，把隐藏推迟到关闭流程之后
- `HideToTray()` 里固定顺序：**先** `ShowInTaskbar = false`，**再** `Hide()`，最后补一次 `Visible = false` 兜底
- 恢复显示时同样把 `ShowInTaskbar = true` 放在 `Show()` 之前

### 顺带新增：关闭按钮行为可选

「设置与工具 → 启动与关闭」新增一个开关：

- **关闭时：最小化到托盘**（默认）—— 点 X 后隐藏到右下角托盘，继续到点提醒
- **关闭时：直接退出** —— 点 X 就真正结束程序

选「直接退出」时，程序会走完整退出流程（停掉提醒定时器、移除托盘图标、结束进程），不会留下后台进程。

### 顺带修的托盘退出逻辑

- 主窗口被真正关闭时，`ApplicationContext` 现在会**自动结束整个程序**（之前窗口关了、进程还赖着不走）
- `Quit()` 加了 `_quitting` 标志，避免「托盘退出 → 关闭窗口 → 又触发退出」的重复调用

### 自检

新增 `StudyCompanion.exe --closetest`：离屏建窗口，用两条关闭路径验证最终状态，输出 `closetest.txt`。

```
【场景 1】设置 = 最小化到托盘
  窗体 Visible      = False    期望 False      ✔
  ShowInTaskbar     = False    期望 False      ✔
  系统认为窗口可见  = False    期望 False      ✔
  窗体已销毁        = False    期望 False      ✔（进程要留着提醒）

【场景 2】设置 = 直接退出
  窗体已销毁        = True     期望 True       ✔
  系统认为窗口可见  = False    期望 False      ✔
```

> 说明：这个离屏测试能验证「隐藏 / 退出」的最终状态，但**验证不了屏幕上的实际观感**（测试时窗口在屏幕外、且没有真实消息循环）。本次修复主要依据的是 WinForms 的标准写法：`BeginInvoke` 推迟隐藏 + 先设 `ShowInTaskbar` 后 `Hide`。

## v1.1 —— 修复「点击日历导致界面抖动」

抖动是布局死循环造成的，三个根因都已修掉：

1. **列宽依赖滚动条**：原来列宽按 `ClientSize.Width` 计算，而竖向滚动条出现/消失会改变它 → 宽度变 → 卡片文字换行数变 → 卡片高度变 → 滚动条又切换 → 面板 `Resize` 再次触发布局，来回振荡。
   现在列宽一律按「面板宽度 − 预留滚动条宽度」计算，与滚动条状态无关，布局一次收敛。
2. **没有重入保护**：`Resize` 在布局过程中被再次触发会递归刷新。现在加了 `_busy` 重入锁，内部布局走不设锁的 `DoLayoutLeft / DoLayoutRight`。
3. **重建控件导致闪动**：原来切换日期会销毁并重建整列卡片，点「标记完成」也会整列重建。现在
   - 重建前用 `WM_SETREDRAW` 冻结重绘，完成后再一次性刷新
   - 点击**同一天**不再触发任何刷新
   - 打卡只做轻量刷新（`RefreshLight`），不重建控件
   - 修掉了「遍历 `Controls` 的同时 `Dispose`」的隐患

另外修掉了日历控件同时用 `Dock = Top` 又手动 `SetBounds` 造成的定位冲突，以及每次布局都重复挂载 `Paint` 事件的无用操作。

自检命令 `StudyCompanion.exe --layouttest` 可复现验证。

按需求实现的基础功能：

- 支持课表被 WPS 占用时使用缓存兜底
